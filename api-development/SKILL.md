# API Development

## 发现当前架构与合同

读取目标仓库适用的 AGENTS.md 和接口规则。使用仓库指定的代码索引工具；不可用时使用限定目录搜索。不要预设框架、语言、目录、数据库、文档格式或外部同步平台。

从用户提供的接口、字段、客户端或现象找到：

```text
路由或操作定义 → 认证与授权 → 入参解析/校验
→ 业务处理 → 数据访问及外部依赖 → 响应序列化
```

按实际架构映射到 Controller、Handler、Resolver、Service、Request、DTO、Resource 等，不强行引入新分层。识别共用实现和关联客户端，限定本次变更影响面。

明确允许修改的行为、需要保留的合同和授权边界。合同不仅包括路径、方法与字段，还可能包括类型、默认值、可空性、分页、错误码及条件输出。“结构不变”不能被解释为可任意改变语义。授权与范围从现有上下文推导，实质歧义无法消除时才询问。

## 实施最小改动

- 在现有架构中负责该行为的层修改，优先复用已有校验、业务规则和序列化约定。
- 区分客户端、角色和操作场景。列表可选过滤不能削弱创建/编辑的必填校验；单端响应需求不能无意改变共享输出。
- 查询与聚合核对实际适用的租户、组织、门店、团队、本人、辖区、任期、时间和状态范围；列表、计数、排名及导出需要一致时复用同一业务过滤。不要给没有这些概念的项目强加字段。
- 不混用用户、身份、成员关系或任职记录 ID。授权依据与业务数据所有权分别核对。
- 涉及资金、库存、重试、回调或并发时，按项目规则核对事务、幂等与失败补偿。外部受理不等于最终业务成功。

## 验证实际行为

按风险和仓库要求选择能证明变化的最小验证，不固定要求每次都新增测试。需要回归测试时构造能区分旧行为和新行为的数据，例如交叉租户访问、与 ID 顺序相反的排序、不同校验场景或重复请求。

执行适用的语法、类型、编译、相关测试和差异检查。会访问数据库或外部服务的测试先核实隔离环境与副作用，不让测试改变共享业务数据。明确列出未执行的必要验证及原因。

## 同步合同产物

先识别项目的合同来源：代码生成定义、手写 OpenAPI、GraphQL schema、protobuf、接口说明或其他机制。用项目已有方式更新，避免手工修改会被覆盖的生成文件。

- 参数、响应和示例来自实际代码或 schema，覆盖相关分支、枚举、分页和可空性，不凭字段名猜测。
- 示例语言、占位方式和测试数据按项目规范，避免真实敏感数据；不将某个项目的中文占位要求推广到所有 API。
- 纯文档请求只修改文档和相关产物，不为迎合示例修改实现。
- 外部同步仅在用户授权或适用项目规则要求时执行。使用可用的对应工具/Skill，限定到本次接口，保护已有认证、公共参数、脚本及人工配置。
- 验证生成/解析结果及必要的远端读回；缺少凭据或服务不可用时完成本地部分，明确区分本地完成与外部同步。

最终报告实际接口或操作、行为及合同变化、验证和阻塞。保持合同不变时明确说明。提交、推送、部署按用户独立授权处理，不由接口修改自动触发。
